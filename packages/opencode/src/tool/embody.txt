Dispatch a character subagent to sample a character's in-character state from objective inputs plus stable self-knowledge.

The Director calls this tool to collect structured character output. You (the Director) must:

1. **Pass objective external facts**
   - Prefer `sceneFacts` for what the character can directly perceive right now.
   - Prefer `situationFrame` for the objective event frame of the current moment.
   - When exact current interaction detail matters, pass `sceneEvents` as structured JSON objects so speech lines, outward actions, and objective results are not flattened into Director summary prose.
   - Legacy `l2View` and `situation` still work, but are deprecated.

2. **Keep subjective interpretation out of objective fields**
   - `sceneFacts`, `situationFrame`, `sceneEvents`, and `focusHints` must not contain thoughts, judgments, decisions, or finished conclusions.
   - Do not write lines like `you realize`, `you suspect`, `你意识到`, `你怀疑`, `你打算`.
   - `sceneEvents` may include only observable material: direct `speech`, outward `action`, and objective event/result fields.
   - Never include any character's `inner_thought`, emotion label, hidden intent, private plan, or similar subjective field in `sceneEvents`.
   - Do pass visible, audible, tactile, olfactory, spiritual, and bodily information.

3. **Let the runtime inject stable layers**
   - The system will add self-knowledge from character config and state.
   - The system will add objective environment from `runtime.yaml`.
   - The system will add current body state from `runtime.yaml` and available state data.
   - The system will add baseline sensory profile and current effective sensory state when possible.

4. **Use `playerNudge` only for weak steer**
   - `playerNudge` is optional.
   - It may bias attention or lean, but it is not a fact and must not be phrased as an already-finished inner conclusion.
   - If the player did not explicitly ask for directional influence, leave `playerNudge` empty.
   - Do not use `focusHints` to inject conclusions like `she is testing you` or `he means no harm`. Keep hints sensory and external.

5. **Translate raw numbers into perceptible experience when needed**
   - Do not write `power level 2500`.
   - Write what the character would detect, such as `you sense formidable spiritual pressure`.

## Output Contract

This tool returns a compact character sample:

- `inner_thought`: the character's private internal monologue
- `speech`: the exact words spoken aloud, or an empty string if silent
- `action_intent`: what the character intends to do next
- `outward_action`: immediate visible behavior, gesture, or movement, or an empty string if none

The character subagent is instructed to return exactly one JSON object with those four string fields and nothing else.
The runtime still tolerates minor formatting drift and passes the sample back instead of aborting the whole turn, but you should continue reasoning as if JSON is the contract.

The character subagent does not decide final outcomes and does not write the final scene narration. The Director must consume these samples, coordinate the scene, decide outcomes, and present the player-facing prose.

After calling this tool, the Director should continue the turn and produce the visible narrative result. Do not stop at raw samples. Prefer consolidating the outcome into a single `narrate` call or an equivalent complete Director-written narrative passage.

## Important

- Never paraphrase or hint at God Only information in objective inputs.
- The system programmatically strips any remaining God Only content from self-knowledge and objective inputs as a safety net.
- The system also rejects structured event payloads that leak another character's private subjective state.
- Objective inputs should contain enough immediate scene facts for action, but should not be padded with omniscient lore.
- Do not ask the character subagent for outcome plans or omniscient narration.
- This tool returns structured character samples — you then continue directing the scene.
